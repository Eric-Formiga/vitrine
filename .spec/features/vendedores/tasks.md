- Notas: primeira tarefa. Módulo `sellers` (ADR-0002) com tabela `sellers` (DATA_MODEL) mais `document_encrypted`, `document_hash` (único), `main_category_id`, `instagram`, `rejection_reason`, `rejected_at`, `suspension_reason`, `suspended_at`; `user_id` e `slug` únicos. CPF/CNPJ: validação dos dígitos verificadores no domínio (`tax-id.ts`); guardado com AES-256-GCM e hash HMAC-SHA256 dos dígitos (ASM-016), atrás da porta `DocumentVault`. A chave vem de `SELLER_DOCUMENT_KEY` (32 bytes em base64, obrigatória na subida; os testes usam uma chave fixa no `vitest.config.ts`). O `slugify` sai de `catalog/domain` para `shared/text` (as categorias passam a importar de lá; o mapeamento da T-008 aponta para o caminho novo). A conferência usa a porta `PaymentGateway` (`lookupPixKey`) e a regra `assertPixKeyOwner` da T-012: 404 do Asaas → `PIX_KEY_NOT_FOUND`; titular diferente → `PIX_KEY_OWNER_MISMATCH` (os dois com status 422); qualquer outra falha do provedor (`PaymentProviderError`, `PaymentGatewayNotConfiguredError`, timeout) → `PIX_KEY_CHECK_UNAVAILABLE` (503). A ordem é: validar o formato, checar a unicidade (conta, slug, documento) e só então consultar o Asaas. Rejeitada há 7 dias ou mais: a mesma linha volta para `PENDING` com os dados novos (AC-047). `SLUG_TAKEN` e `DOCUMENT_TAKEN` vêm do índice único do banco (P2002), não de um "checa antes", como em categorias. `GET /v1/seller/application` (👤) devolve a candidatura da pessoa, com o documento mascarado e o checklist (`store`, `pixKey`, `shipping`; `shipping` fica pendente até a T-018). Os testes usam o gateway falso do `createApp({ paymentGateway })` (T-015), com o kit em `seller-test-kit.ts`. Regenerar o contrato (`pnpm api:generate`). Feito assim: o `PaymentsModule` virou global (a porta `PaymentGateway`, inclusive a falsa dos testes, serve o módulo `sellers`); o `DomainError` ganhou `extensions` (membros extras do problem+json, RFC 9457), para o 409 levar `canReapplyAt`; o `startTestApp` aceita `paymentGateway`. O cofre deriva duas subchaves (cifra e hash) da `SELLER_DOCUMENT_KEY` por HKDF.

Formulário com Server Action: os erros da API (`errors[]` por campo do 400, e os códigos 409/422/503) viram mensagens junto ao campo, e o que foi digitado continua no formulário (AC-058); sucesso redireciona para `/minha-loja`. Os testes renderizam os componentes com `react-dom/server`, como o `category-menu.spec.tsx`. O cabeçalho ganha o link "Vender" (ou "Minha loja", para quem já tem candidatura).
